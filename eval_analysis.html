ABSA Triplet Evaluation — Pipeline Analysis

So sánh chuẩn: Không có split LLM vs. Có split LLM cho bài toán Joint Triplet (aspect term, category, sentiment)

1. Hai Pipeline Được So Sánh

Pipeline A — Không có Split LLM
1Input: câu gốc test.apc — 312 sentences, 312 gold triplets
2ATE: NER model (BERT/T5) chạy trên full sentence → trích xuất aspect terms
3Joint Head: FastLcfBertMultiTask nhận (sentence, term) → predict (category, sentiment)
4Gold match: theo sentence text từ test.apc
✓Output: eval_joint_triplet_BERT.csv
Pipeline B — Có Split LLM
1Input: results.csv — 312 entities, LLM tách thành 612 units (avg 1.96 unit/entity, 174 entities bị tách)
2ATE: GAS T5 chạy trên từng unit (clause) → extract term
3Joint Head: FastLcfBertMultiTask nhận (gold sentence, term) → predict (category, sentiment)
4Gold match: theo entity_id từ test_sentences_id.csv
✓Output: eval_results_BERT.csv
Cùng gold set — so sánh hợp lệ
Cả hai pipeline đều đánh giá trên 312 gold triplets — test.apc và test_sentences_id.csv là hai format của cùng một test set. TP + FN = 312 cho cả hai. So sánh Micro P/R/F1 là trực tiếp và chuẩn.

2. Metric Định Nghĩa (Chuẩn ABSA Triplet)

TP (True Positive)
predicted ∩ gold
Triplet predict đúng cả 3: term + category + sentiment phải khớp chính xác
Micro Precision
TP / (TP + FP)
Tỉ lệ predict đúng trong tổng số predict. Phạt khi predict nhiều sai.
Micro Recall
TP / (TP + FN)
Tỉ lệ gold được tìm thấy. Phạt khi bỏ sót gold triplets.

7. Insights Cho Paper

Tại sao Split LLM tệ hơn?
LLM tách 312 câu gốc thành 612 units (1.96×). GAS T5 ATE chạy trên từng unit nhỏ nên extract nhiều hơn — nhưng phần lớn là spurious terms. Kết quả: FP tăng gấp 3× (93 → 302), recall chỉ cải thiện nhẹ (+2.25 pp), dẫn đến F1 thấp hơn 16.38 pp. Joint head vẫn nhận full sentence (không phải unit), nên LCF contextual features không được hưởng lợi từ việc tách clause.
Cách viết trong paper (Experimental Setup)
Dùng Micro F1 làm primary metric (chuẩn ABSA triplet evaluation, e.g., ASTE-D, SpanASTE). Report thêm Macro F1 để phản ánh minority class. Oracle metrics để tách biệt lỗi ATE vs lỗi phân loại. Nên trình bày bảng so sánh với 3 nhóm: (i) ATE-only F1, (ii) End-to-end Triplet F1 (no split), (iii) End-to-end Triplet F1 (split LLM).
Kết luận cho paper
Pipeline không split LLM đạt triplet Micro F1 = 70.19% (best: lcf_seq_cdw_resize), cao hơn pipeline split LLM 16.38 pp (53.81%). Dù split LLM tăng recall nhẹ (+2.25 pp), precision sụp đổ (70.19% → 42.80%) do hallucinated/over-extracted terms. Oracle analysis xác nhận joint head chất lượng cao (86.86% joint accuracy) — bottleneck là ATE (78.85% F1).
